# Cost register

Rule 1 and W3: every item has a low/central/high value, unit, currency and price year, a source and a status. Never fill a gap with a guess; write `status: unknown` and leave the values null.

## Item schema (`CostItem` in `common/schemas.py`)
```yaml
- id: C-line-hsr-flat-001
  item: HSR double track, flat desert, civil works and track
  category: line_type          # line_type | terrain | structure | system | station | depot | rolling_stock |
                               # signalling | electrification | power | land | utilities | design_pm |
                               # contingency | opex | renewal | financing
  line_type: hsr               # hsr | conventional_passenger | mixed | commuter | upgrade | n/a
  terrain: flat_desert         # flat_desert | dunes | sabkha | escarpment_mountain | coastal | n/a
  unit: SAR_m_per_km           # SAR_m_per_km | SAR_m_per_station | SAR_m_per_trainset | SAR_m_per_yr |
                               # SAR_per_train_km | pct_of_capex | pct_per_yr | SAR_m_lump
  currency: SAR
  price_year: 2024
  low: 45
  central: 60
  high: 85
  source: S-031                # or `assumed`
  status: sourced              # sourced | derived | assumed | unknown
  derivation: "converted from EUR 2019 using index I-eur-sar-2019-2024 (see docs/costs.md)"
  notes: "Spanish AVE flat-terrain packages, adjusted; sand mitigation excluded (see C-terrain-dunes-001)"
```
`cities/ksa/costs/index.yaml` is the project's **only** price and FX index (CP2 P2a, 31 Oct 2026; the cost register and the W5 benchmark tables both use it; the former `index-r1b.yaml` is folded in and deleted). It is generated by `uv run python -m costs.index_build`; never edit it by hand and never create a second index. Rule (A-cost-002): SAR items are inflated with the Saudi CPI (GASTAT, relayed by WDI); foreign-currency items are inflated with the source economy's GDP deflator (World Bank WDI) **before** conversion, then converted at the 2025 rate to USD and at the peg 3.75 to SAR; sensitivity = convert at the price-year rate, then the Saudi CPI (ids ending `-cti`). Series exceptions are registered in A-cost-307 (EUR outside the euro area: Eurostat EA20 deflator; AED: UAE CPI). Factor rows: `id, method, from_currency, from_year, to_currency, to_year, factor, source, price_series` and, for per-economy EUR rows used by the benchmarks, `country`; a derived item must name its index factor in `derivation`.

CLI: `uv run python -m costs.register validate cities/ksa/costs/cost_register.yaml`; `uv run python -m costs.register normalise --to SAR --price-year 2024` (writes `cost_register.normalised.yaml`, never edits the source file); `uv run python -m costs.estimate --corridor <id> --register ... --uplifts cities/ksa/costs/uplifts.yaml --seed 1 --out runs/costs/<id>/` gives P10/P50/P90 capex and opex per corridor.

## Bottom-up and top-down
- **Bottom-up:** per km by line type and terrain; structures as alignment shares (tunnel, viaduct); stations by class; depots; rolling stock per trainset; signalling (ERTMS level); electrification vs diesel/hybrid/hydrogen; power supply; land and utilities; design, project management and contingency; opex (train operation, energy, maintenance of way incl. sand, staffing with the Saudisation share); renewals over 30–60 years; interest during construction and financing structure.
- **Top-down:** cost per km from completed projects (from the benchmark dossiers, price-year adjusted) and the KSA data points: Haramain HSR, SAR North and East lines, Riyadh Metro, Landbridge estimates (SR100 bn / USD 26.6 bn vs USD 7 bn: both recorded, conflict flagged).
- **Reconcile** in `docs/costs.md`: per line type, bottom-up P50 against the top-down range; a gap over 30 % is explained or flagged, never averaged away.

## docs/costs.md
Version header; label; the index table; the register by category with sources and statuses; KSA data points with citations and conflicts; reconciliation table; the uplift policy (`reference-class-forecasting`); what is unknown.

## Acceptance (W3)
Every corridor family has a capex/opex range traceable to register ids; every KSA data point is cited or marked unknown; `validate` passes; every `assumed` item is in the assumptions register (`A-cost-nnn`).
