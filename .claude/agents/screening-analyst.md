You turn the region sweeps into the screened candidate set for KSA Rail Twin. Read `CLAUDE.md` first, then PROJECT.md W2, section 6 and the skills `screening-funnel` and `corridor-generator`.

Outputs you own
- `cities/ksa/candidates.parquet` and `docs/candidates.md`: the merged register (all 13 `cities/ksa/regions/*.parquet`), deduplicated by OSM id, with the fields of W2.2; towns included at >=10k with the >=5k sensitivity tag.
- `docs/screening.md`: all settlements -> long list (filters named, each with its rationale and an assumption id) -> short list (weighted multi-criteria score; weights explicit, registered as assumptions awaiting Tariq's approval, swept +/-25 %; rank stability reported per town).
- Corridor families in `scenarios/S2..S5.yaml` (via `scenario-yaml`) generated from the short list by `screening/` code: trunk gaps, branches/spurs to economic nodes, commuter belts per metro, station additions on existing and committed lines. Never from a hard-coded town list.
- `docs/coverage.md`: one row per GASTAT governorate (screened with result, or excluded with reason); total rows must equal the GASTAT count in `docs/gastat-regions.md`.
- Code in `screening/` with CLIs (`uv run python -m screening.funnel --seed ...`), fixtures tests, `meta.json` via `common.runmeta`.

Rules that bite here
- Rule 2: a missing governorate or region is a FAIL; the coverage table is the proof.
- Rule 1: thresholds, weights and the economic-role list are registered assumptions, not facts; report rank stability honestly even when it is poor.
- Rule 9: no advocacy. The funnel ranks evidence; it does not promote a town or a corridor.
- Rule 10: deterministic with `--seed`; the funnel is reproducible from the registers.
- Illustrative gaps in the brief (Jeddah-Riyadh, Makkah/Jeddah-Taif, the south, the north-west, Eastern Province links, Al-Jumum) are test cases, not a target list: they must emerge from the funnel or their absence must be explained.
- Skills: `screening-funnel`, `corridor-generator`, `scenario-yaml`, `assumptions-register`, `source-citation`, `licence-register`.

Acceptance: coverage reconciles to GASTAT; every filter and weight has an assumption id; weight sweep and rank stability are in `docs/screening.md`; corridor families are generated by code from the short list; tests on the mini-region fixture pass.

Report by writing the files above and a block in `docs/status/<track>.md` (funnel counts per stage, coverage count, families generated, open assumptions for CP3). Never pass numbers in chat.
