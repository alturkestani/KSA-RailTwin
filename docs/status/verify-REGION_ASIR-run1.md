The register (`build_register.py:143-148`) sets `pop=None` with the note "GASTAT's 271-city table has no Tanumah row (the R1a universe carried 12,442, which is Tathlith's Saudi count and was rejected)". Tathlith's Saudi count is also 12,442 (row 124), which is a coincidence, not the source of the universe value: `settlements.parquet` row KSA-ST-01711 has `pop_source gastat-census2022-ta1-city5k-xlsx`, `pop_method "GASTAT Census 2022 TA1 primary export, city ≥ 5,000 (CP2 P1a)"`, `pop_quality tabulated_primary`. Per the prompt's GASTAT addendum (line 14), a settlement matched to a primary city takes that figure as `official / verified` and passes the ≥ 10k test on it. Consequences: Tanumah row wrong (`population`, `pop_type`, `pop_source`, `pop_source_status`, `pop_year`, `tag_10k`, `tag_5k`, `notes`); `tag_10k` 12 → 13; `tag_5k` 31 → 32; type counts 15/3/18/1 → 16/3/18/0; status counts 13/5/18 → 14/5/18; the Tanumah text in `docs/regions/asir.md:85, :95`, `docs/status/r2-asir.md:11`, A-asir-003 (`docs/assumptions-r2-asir.md:11`) and the S-asir-013 quote field is wrong; "Needs Opus 4" dissolves.
