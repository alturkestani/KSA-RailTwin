## 4. Judgement on rows with low = central = high (53 of 188 valued rows)

- **In the register: acceptable.** They are "as published" single figures (award values, lump sums, one-off per-trainset derivations). `docs/costs.md` §2 line 34 states the convention, each row's `notes` says "single figure as stated by the source", the schema distinguishes them from `assumed` rows (which must have low < high: `tests/test_costs_register.py` lines 142–144), conflicting figures for the same thing are separate rows, and none of them is presented as an estimate. Rule 3 bites on modelled outputs and estimates, not on recording what a source printed; inventing a spread would breach rule 1.
- **In the estimator: a gap to close before R4.** Four of the fixture's 22 traced components use a single-figure row as the sole default and therefore carry P10 = P50 = P90 in `trace.csv` (`power_substations` 246.9, `station[intermediate]` 395.8, `station[terminal]` 791.6, `depot` 625.2, `rolling_stock[electric]` 611.9 SAR m): about SAR 2.67 bn, 28 % of the base P50 capex, enters with zero spread. The totals are still ranges (the other components and the reference-class uplift supply the spread, as §2 says), so this is not a single-point cost *presented*, and R1c's acceptance criteria are met. But `costs/config/estimate_map.yaml` defaults should not rest on zero-spread rows when R4 costs real corridors: give those components a spread from the alternative rows already in the register (e.g. `C-station-hhr-pkg2-per-station-001`, `C-depot-regional-de-002`, the CAF/Stadler/Talgo trainset rows) or an `assumed` spread with an A- id. Fix 1 below.
- Related proxy to keep visible: `rolling_stock[electric]` maps to a *diesel* trainset price (`C-rollingstock-ic-diesel-sar-caf-008`, declared as A-cost-015).
