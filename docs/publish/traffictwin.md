# TrafficTwin dependency: what the public repository needs and what it does not (PUBLISH_PREP item 3)

TrafficTwin Jeddah is the author's earlier city-scale project. **It stays private for now (Tariq, 12 Nov 2026, Q6): it is an optional private companion, not required to run, test or reproduce this repository, and nothing new from it is vendored.** README, `CONTRIBUTING.md`, `NOTICE` and `CITATION.cff` say so and no longer link it; the licence register keeps the URL as provenance, labelled private. The data manifest rows (`cities/ksa/sources.yaml`) and the verbatim brief and records (`PROJECT.md`, `prompts/`, `docs/status/`) keep the URL as written. On the author's Mac it is a separate, **read-only** checkout (`~/Documents/Projects/TrafficTwin`). This repository reaches it in two ways: three gitignored symlinks (`data/osm`, `data/jeddah`, `data/traffictwin`, made by `make data-links` / `scripts/link_data.sh`), and one module (`coupling/jeddah.py`) that imports its policy schema and prints its simulation command. **The public repository runs without it:** `make setup && make test && make demo` passes in a clean clone with no TrafficTwin, no symlinks and no `data/` beyond the committed tables (`docs/publish/checklist.md` §6). This run wrote nothing to the TrafficTwin checkout and ran no command there. The local `make test` on the author's Mac imports its policy schema read-only, as it always has (`tests/test_coupling_jeddah.py`). The commit message of 3a8fe84 says "not read", which is too strong for that reason; this sentence corrects it.

Every reference, line by line, is in [`traffictwin-references.csv`](traffictwin-references.csv) (file, line, kind, text).
