## Tasks
1. **Zones**: governorate-level zones Kingdom-wide and finer zones around each metro (the CP1 metro list; use R1a settlements and OSM admin boundaries, ODbL); `cities/ksa/zones/zones.geojson` with population, jobs proxy (sourced or flagged proxy, e.g. LFS regional shares, night lights flagged), and the economic nodes attached. `uv run python -m demand.zones build --seed 1 --out runs/zones/`.
2. **Population scenarios to 2050/2060** (`cities/ksa/population/scenarios/`): GASTAT projections if published (cite), UN World Population Prospects latest revision low/medium/high (download the small CSV, register it with licence), urbanisation trend, Vision 2030 targets as a labelled policy scenario; giga-projects (NEOM, Red Sea, Qiddiya, AlUla, Diriyah, others from R1a) as add-on scenarios with explicit `announced` vs `delivered` uncertainty ranges and sources. `docs/population-scenarios.md` with every number sourced; nothing invented for unpublished sub-national projections (write the method used to downscale and register it as an assumption).
3. **Gravity model** (`gravity-calibration`): doubly-constrained gravity by purpose (commute, business, leisure/VFR, pilgrimage, tourism) with impedance functions as registered assumptions; freight OD where open data allows (else "no open freight OD found"); `uv run python -m demand.gravity run --scenario S0 --population baseline --seed 1 --out runs/demand/S0-baseline-s1/` writes OD Parquet per purpose plus `meta.json`.
4. **Mode choice** (`modechoice/mnl.py`): multinomial logit car/rail/air/bus generalised from TrafficTwin's `docs/loop-mode-choice.md` (read-only); coefficients from `mode_choice_priors.yaml` (literature-based, each sourced), a coefficient sweep like TrafficTwin's, generalised-time components (in-vehicle, access/egress with the summer first/last-mile penalty from `isochrone-commute`, wait, fare / VoT); outputs shares per OD and purpose with the sensitivity band. Label: "coefficients literature-based until survey results exist".
5. **Calibration** (`demand/calibrate.py`): compare modelled totals with observed totals (GASTAT rail passengers 2023, HHR ridership, GACA domestic air pairs, bus facts from `docs/data-sources.md`); report GEH-style or percentage deviations per total; adjust only registered parameters within their stated ranges and log every adjustment; a total passes only if the deviation is within the tolerance written in `cities/ksa/assumptions/demand_calibration.yaml`. The status label flips to `calibrated` per total, never globally.
6. **Tests** on the 6-zone fixture: gravity constraints hold (row and column sums), determinism, MNL shares sum to one, sweep monotonic where expected; all under 20 s.
7. **Docs**: `docs/demand.md` (method, inputs with source ids, outputs with run ids, calibration table, what is calibrated and what is not), `docs/mode-choice.md` (coefficients with sources, sweep results, the 30-minute commute lens inputs), registers.
8. **Handoff** (`milestone-handoff`): `make test`, `red-team-verifier`, commits per task, status block in `docs/status/r3.md` (zones count, scenarios written, OD totals per purpose with run ids, calibration deviations, elapsed). Write the **CP4 decision list** (calibration acceptance per total, population scenario set, giga-project add-on treatment) into `docs/STATUS.md`. End with `R3: done` or `R3: blocked - <reason>`.
