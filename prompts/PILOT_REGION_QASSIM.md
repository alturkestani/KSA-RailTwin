## Schema and working rules (merged PILOT_MERGE schema, CP1_PREP 31 Oct 2026)
- Field names are exactly those of `common/schemas.py:RegionRow` (table in the `region-sweep` skill): `osm_id` **and** `osm_type` (node/way/relation; ids overlap across types), `dist_existing_km`, `nearest_existing`, `dist_committed_km`, `nearest_committed`, `nearest_committed_station`, `dist_metro_km`, `nearest_metro`, `nearest_metro_tier` (1/2/3, A-screen-013), `road_min_*`, `road_min_method`, `dist_method`, `tag_10k`, `tag_5k` (never `threshold_5k`), `notes`.
- Population provenance: `pop_type` is `official` / `derived` / `grid` only. A GASTAT figure relayed by an aggregator (e.g. citypopulation.de) is `pop_type: official` + `pop_source_status: secondary` + `primary_to_find: <the GASTAT table>`; a figure read on GASTAT itself is `pop_source_status: verified`. Never `pop_type: secondary`. Use the settlement (place/locality) figure, never the governorate total, for a town row.
- `terrain_class` uses the schema words only: `flat_desert`, `dunes`, `sabkha`, `escarpment_mountain`, `coastal`, `mixed` (not `sand_dunes` or `coastal_plain`).
- `economic_roles`: list of `{role, source}` with role in `port, industrial_city, mining, tourism, heritage, hajj_umrah, airport, university, giga_project, agriculture, border_crossing, military, administrative, energy` (`energy` = refineries, oil/gas processing, export terminals). Every role names an `S-` source that ties it to that town; an empty list means "none sourced", say in `notes` if roles were not assessed.
- `threshold_50k` (population ≥ 50,000) and `pilot_sample` (with the reason in `notes`) are pilot-only columns: set them in this pilot.
- Assumption ids are prefixed by your slug (`A-qassim-001`, ...), never the shared `A-screen-pilot-00n`.
- **Scripts and raw files:** every builder or helper script lives in the worktree under `screening/sweeps/qassim/` and is committed; never write scripts to `/tmp`. Raw downloads (Nominatim/Overpass JSON, census tables) go under `data/ksa/qassim/raw/` (gitignored) and get a row in `cities/ksa/sources.yaml` (`uv run python -m common.manifest add ...`) before anything is computed from them.
- **Status line:** the last line of your status block is plain text at the start of the line, with no backticks, bold, bullet or indentation: `PILOT_REGION_QASSIM: done` or `PILOT_REGION_QASSIM: blocked - <reason>`.

## Tasks
1. **Governorates.** Take GASTAT's official list of governorates of Qassim (if `docs/data-sources.md` already records it from DATASCOUT_1H, use that `S-nnn`; otherwise find it on stats.gov.sa / portal.saudicensus.sa and record it). Write `governorates_gastat: <n>` in the register header. Every governorate gets at least one row: its centre (المركز الإداري), even if small.
2. **Towns ≥ 50,000.** Add every settlement in the region with Census 2022 population ≥ 50,000 (official GASTAT city/locality table first; a secondary aggregator only with `pop_type: official` replaced by `secondary` and `primary_to_find` filled). Tag `threshold_50k: true`.
3. **Stratified sample of smaller towns.** Add 4–6 towns between 5,000 and 50,000 chosen to span: near (< 25 km) and far (> 100 km) from an existing rail line; with and without a sourced economic role (port, industrial city, mining, university, heritage/tourism, Hajj/Umrah, airport, giga-project). Tag `pilot_sample: true` and write the sampling reason in `notes`. For Qassim prefer towns that test a schema edge (a governorate centre smaller than a non-centre town, a town split across governorates, an unmapped OSM place).
4. **Every row, every field** of the `RegionRow` schema: `name_ar`, `name_en`, `region`, `governorate`, `governorate_ar`, `osm_id` and `osm_type` (from OSM Nominatim/Overpass read of `place=*`; ODbL), `lat`, `lon`, `population`, `pop_source` (S-id), `pop_year`, `pop_type` (official/derived/grid), `pop_source_status`, `primary_to_find`, `tag_10k`, `tag_5k`, `threshold_50k`, `dist_existing_km`, `road_min_existing`, `nearest_existing`, `dist_committed_km`, `nearest_committed`, `nearest_committed_station`, `dist_metro_km`, `nearest_metro`, `nearest_metro_tier`, `economic_roles` (list of `{role, source}`; enum above incl. `energy`), `terrain_class` (flat_desert / dunes / sabkha / escarpment_mountain / coastal / mixed; from SRTM/Copernicus description or a cited geography source, else assumed with an `A-qassim-` id), `source_ids`, `exclusion_reason` (empty unless excluded). Distances in the pilot are great-circle from published coordinates (`method: haversine`, registered as assumption `A-qassim-001`); road minutes stay empty with `road_min_method: pending R1a skims`. Line and station locations come from `cities/ksa/lines/*.yaml` if present, else from SAR/HHR published station lists (cite) — committed lines (Landbridge, GCC, Riyadh Rail Link) are `layer: committed`, never "existing".
5. **Write the register**: `uv run python -m screening.region_sweep validate cities/ksa/regions/pilot-qassim.parquet` must pass (it checks every row against `RegionRow`, the CSV mirror and the `governorates_gastat`/`governorates_listed` Parquet header; write both header keys). Write `docs/regions/pilot-qassim.md`: version header; governorate count GASTAT vs listed; the rows as a table; the sample's rationale; exclusions with reasons; sources; "Needs Opus judgement"; label "screening input, not a forecast".
6. **Handoff**: `uv run python -m common.docver check docs`, commit (`feat(screening): pilot sweep qassim`, including `screening/sweeps/qassim/`), status block in `docs/status/pilot-qassim.md` (rows written, governorates GASTAT/listed, towns ≥ 50k, sample size, facts verified/secondary/unverified, elapsed time). End with `PILOT_REGION_QASSIM: done` or `PILOT_REGION_QASSIM: blocked - <reason>`.

## Acceptance (the verifier checks these)
- `governorates_listed == governorates_gastat` for Qassim, or the discrepancy is flagged with both sources.
- Every row has `pop_source`, `pop_year`, `pop_type`; no population without a source id; no distance without a method.
- No planned/committed line is labelled existing; every economic role names a source.
- The stratified sample has 4–6 rows with `pilot_sample: true` and a reason each.
- Parquet and CSV agree (same row count, same ids); the Markdown table matches the Parquet.
