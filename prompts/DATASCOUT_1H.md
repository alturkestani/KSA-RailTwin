# DATASCOUT_1H — one-hour grounding verification pass (main checkout, section 10.3)

You run as the `rail-data-scout` agent (bulk on `claude-haiku-5-5`; escalate ambiguous rows to the coordinator by writing them under "Needs Opus judgement" in your status block, never by guessing). This is network research only: WebSearch, WebFetch, reading. **Time-box: 60 minutes of wall time** from your first tool call (note the start time in `docs/status/main.md`). At 60 minutes stop, write what was verified and what was not, and hand off. No download over 50 MB; nothing under `data/` except small tables registered with `common.manifest` (disk gate: about 17 GB free, no PBF or grid downloads).

Skills: `source-citation` (every record is an `S-nnn` row), `assumptions-register`, `licence-register`, `milestone-handoff`.

## You own
`docs/data-sources.md`, `docs/sources/index.csv`, `docs/sources/index.md`, `docs/sources/conflicts.md`, `data/ksa/tables/` (small tables + `README.md` per table), new rows in `cities/ksa/sources.yaml` (via `common.manifest add` only), `docs/status/main.md` (your block only).

## Tasks
1. **Section 4 grounding table.** For every row of PROJECT.md section 4 (Haramain HSR, SAR North line, SAR East line, Saudi Landbridge, GCC railway Saudi section, Riyadh Metro, rail ridership 2023, Al-Jumum, Census 2022 city populations) re-verify each fact against the primary source named in the "Source to re-verify" column, then against a second source. Record one `S-nnn` per fact (URL, publisher, title, publication date, access date = today, locator, quote ≤ 25 words, status `verified` / `secondary` / `unverified`, `primary_to_find` when only an aggregator was reachable). Where the brief's starting fact and the source differ (distances, speeds, station names, counts), write both values; never overwrite the brief.
2. **Landbridge cost conflict.** SR 100 bn ≈ USD 26.6 bn (MEED quoting SAR's CEO) vs "USD 7 bn" (ENR, Jun 2026). Find what each figure covers (whole programme vs a phase or a package, price year, currency), record two `S-nnn` rows and an entry in `docs/sources/conflicts.md` with your reading of the scope difference labelled "analysis". Do the arithmetic explicitly in the conflicts entry: SAR→USD at the 3.75 peg (SR 100 bn = USD 26.67 bn; USD 7 bn = SR 26.25 bn, i.e. 26 % of the headline); cost per km for each figure against the stated lengths (~950 km new Riyadh–Jeddah line; "more than 1,500 km of new track" for the programme); and test the hypotheses that USD 7 bn is (a) the first phase, (b) a single package (civil works or systems), (c) a different price year, or (d) a reporting error — each hypothesis with the evidence found or "no evidence". If it cannot be reconciled within the hour, write `unresolved` and the next step; a follow-up `LANDBRIDGE_RECONCILE` run on claude-fable-5-1 reviews your entry. Also record the MEED Projects page for the planned station list (pid=114639) and the status of the "Jamuma" = Al-Jumum identification (Tariq's confirmation is a `stated by project owner` source, not a published one; say so).
3. **GASTAT administrative list.** Find GASTAT's official list of the 13 regions and their governorates (Census 2022 publications or the administrative-divisions table on stats.gov.sa / portal.saudicensus.sa). Record the governorate count per region and the national total as published, with the `S-nnn`. If GASTAT's count differs from another official source (e.g. the Ministry of Interior / Imara lists), record both and flag the difference; this count drives `docs/coverage.md` reconciliation for the whole project. Write the list to `docs/gastat-regions.md` (version header; 13 regions with Arabic and English names, their governorates, the counts, the `S-nnn` and the access date), which the `red-team-verifier` reads.
4. **Population tables.** Identify the best primary GASTAT Census 2022 tables for (a) population by region, (b) by governorate, (c) by city/locality, (d) Saudi/non-Saudi split, and (e) any GASTAT population projection. For each: URL, format (portal table, XLSX, PDF), licence (GASTAT use policy, already analysed in TrafficTwin's `docs/data-sources.md`; cite it), and whether it can be downloaded as a small table. Download at most the governorate and city tables if under 50 MB each into `data/ksa/tables/gastat_census2022_<name>.<ext>` with a `README.md` stating publisher, URL, licence, access date; register each with `uv run python -m common.manifest add ...`. Replace the aggregator city figures of section 4 with the GASTAT values in your table and mark the aggregator rows `secondary`.
5. **Rail facts sampled today.** Sample and record (date-stamped): HHR station list, timetable summary and fare range from sar.hhr.sa; SAR North/East line station lists and lengths from sar.com.sa; Riyadh Metro lines/length/stations from rcrc.gov.sa. Facts only; no scraping beyond reading the published pages.
6. **Write `docs/data-sources.md` v0** in TrafficTwin's source-table format (section per workstream: "In use", "Planned", "Not found / to verify"; columns Source | URL | Publisher/version | Licence or terms | Used for | Commit? | Status) with the version header. Add a "Verified in this pass" table that mirrors section 4 with the verified value, source id and status per fact. Write `docs/sources/index.csv` and `index.md`.
7. **Licences.** Add rows to `docs/licences-datascout.md` / `.csv` (licence-register columns) for every dataset touched (GASTAT use policy, SAR/HHR published facts as facts, MEED/ENR as press facts-only).
8. **Handoff** (`milestone-handoff`, docs-only variant): `uv run python -m common.docver check docs`, `uv run python -m common.manifest verify`, `git add -A && git commit -m "docs(sources): DATASCOUT_1H grounding verification v0"`. Status block in `docs/status/main.md`: start/stop times, facts verified / secondary / unverified (counts), the Landbridge conflict status, GASTAT governorate count found (or not), tables downloaded with sizes, "Needs Opus judgement" list. End with `DATASCOUT_1H: done` (or `DATASCOUT_1H: blocked - <reason>`).
